# 画得自然：构图、结构与用笔

供 `personal-sketchbook` 构思、绘制和审图时使用。这里记录判断方法，不规定每张图长得一样。
用户选择的题材、参考保真程度和喜欢的画法优先；个人非商用是使用范围，不是画面风格。

## 先确定这张画需要保留什么

- 有参考图：先辨认主体，以及让它区别于同类的两三个具体特征。例如杯口偏扁、把手细长、花瓣缺一角、猫背弓起。不要只写“一个杯子”“一只猫”。
- 用户要求照着画：保留关键比例、姿态、机位、物件关系；简化次要细节时，不擅自换成另一套构图。
- 用户要求自由改编：可以裁切、移动、省略或夸张，仍保留用户在意的识别特征。画前用一句话说明主要取舍即可。
- 没明确说改编的参考任务，先采用保守简化；是否可以改变主体或情境会显著影响结果时，再问方向。
- 没有参考图：设计一个可解释的结构和重心，允许想象内容；不要把想象说成用户经历、回忆或真实事件。
- 不默认添加标题、日期、签名、印章或装饰字。用户要求文字时，才安排文字与画的关系。

“无背景”“只画三个物件”“竖写署名”均是可选做法。背景承载情境、方向或光线时，就应保留相应信息。
人物、风景、动物都可以画；复杂关节、肖像相似度和严谨透视需要参考及审图，不能以程序可运行替代这些判断。

## 先把形画对，再决定哪里画得松

自然感不等于给每条线加噪声。先处理主体结构、各部分连接和主次，再选择有理由的不规则。

1. 确认大形：主体是偏长、偏宽、上重下轻，还是一侧伸出去？用尽量少的控制点说明这个差异。
2. 确认连接：杯把接在杯身哪里，叶片从哪段茎长出，头颈与身体怎样接上；不能靠纹理遮住接错的位置。
3. 确认支撑：接触地面的部位、承重方向、遮挡关系和投影要相互一致；悬浮必须是有意表现。
4. 确认轮廓转折：硬物的折角、软布的弯折、骨点的突起，用不同的控制点安排，别统一磨成圆弧。
5. 再放松局部：允许某段轮廓轻微偏离、一次补笔、边缘少画一截；保留整体比例与连接。

观察具体差异，不做平均化符号：

- 两只耳朵可以因头部转向而露出不同面积；随意一大一小不等于观察。
- 花瓣可以有前后遮挡、开合角度和长度差；每瓣随机旋转会丢掉生长结构。
- 窗框、杯口等重复结构先服从同一视角，再允许轻微笔误；各自独立歪斜容易读成变形。
- 自然物的重复有方向和疏密。先定枝条、叶序或毛流，再改变局部形状。

## 构图：让主体有位置，让空处有形状

- 先说清观者首先应看哪里，再安排最大形、最深色、最清楚的边缘。它们可以不在同一个点，但不能处处都争第一。
- 用缩略图检查大形与空白，暂时忽略纹理。主体太小、彼此挤成一团或平均分布，都应先改坐标与尺度。
- 多件物体不要自动排成同尺寸、同间隔的展示柜。可用一大两小、疏密变化、少量遮挡形成节奏；用户要求整齐排列时遵从用户。
- 物件之间的空白也是形：避免几乎接触的两条边、刚好贴住画框的尖角，以及没有意图的细缝。
- 留白不靠固定占比判断。空处应衬托主体的朝向、动作或视觉重量；一味缩小画面不一定更轻松。
- 裁切可以让主体更贴近观者，但别正好切在重要关节或识别特征上，除非这是明确的构图意图。
- 背景有用就画：先用少量大形说明空间，避免所有远处细节与主体同样清楚。

## 线条：不同位置承担不同作用

先区分结构线、暗边、轻描边和纹理线，再为各组选择力度。不要整幅共用一组重描与抖动参数。

- 受力处、遮挡处、主要转折：可更明确、更深，必要时补一笔。
- 迎光处、柔软边缘、远处：可更轻、短缺或只用色差提示。
- 长轮廓：先有方向，再用少量连续偏移形成手势；高频抖动太多会像发毛。
- 短细节：少量明确的笔画通常比许多犹豫小线有效。眼睛、接口等不必复制主轮廓的抖动幅度。
- 重描：只在需要寻找轮廓或压深的片段使用；每条线都双描容易形成统一的描边效果。
- 断线：可安排在亮处、平缓处和次要边缘；不要把所有接点打断，导致结构读不出来。
- 线宽随画幅和对象尺寸调整，但局部识别线仍需单独判断。放大一个物体不等于把全部噪声同步放大。

对照 pencil-case 的轻墨速写时，可看 [纸袋猫方向试稿](../examples/studies/breakfast-cat-v2/artwork.png) 的做法：闭眼与下巴承载表情，肩线接到搭过袋口的前爪，袋面靠少数受力折线和纸白形成。先检查这些连接，再安排断墨；关键连接恰好断掉时，缩图就会变成悬浮的头像或胶囊形的爪。

原版整块填色的猫图仍保留作对照。增加场景、纹理、文件和功能没有自动改善它的姿态；程序化绘制同样需要逐张决定哪一笔值得留下。别把这次轻墨方向扩成所有题材都少画、都不上色的规则：参考若是蜡笔街景，应检查短笔叠色、透纸和笔触方向，而非只降低饱和度。

## 五类笔触如何选择

按要表现的边缘与材质选笔触，不要求每张图集齐五种。具体参数以 renderer 的当前接口为准。

| 类型 | 适合承担的内容 | 容易失手的情况 |
| --- | --- | --- |
| `ink` | 明确的外形、结构接点、少量深边，能留下果断的笔势 | 整圈等粗、等黑、多遍描边，像贴纸轮廓 |
| `pencil` | 轻结构、柔和明暗、少量试探和转折 | 所有线同样灰，主体与细节没有层次 |
| `wax` | 有方向的粗色笔、块面转折、局部厚重的颗粒 | 用同一种颗粒铺满全画，材质和空间都消失 |
| `wash` | 大的明暗或色温关系、半透明色面、有限的水痕 | 每块颜色都溢出且边缘同样深，变成重复特效 |
| `hatch` | 暗侧、转折面、沿形体的细密线组 | 不论形体都用同角度、同长度，或把高光也填满 |

材质的识别优先靠结构、明暗与边缘：

- 玻璃：保留可读轮廓、少量反光和透过物；不必把整件刷成统一浅蓝。
- 金属：亮暗交界可以更明确，反光形状跟随曲面；不靠满屏灰点说明“金属”。
- 布：褶皱从支撑、挤压和垂落处产生；画几条有起因的褶皱，比随机短线更有效。
- 毛与羽：先有身体体积，再沿生长方向加疏密不同的短线；不要用一圈等长刺代替轮廓。
- 陶器和木材：先保留体积与实际特征，再决定是否需要纹理；无明显纹理时允许干净。

## 色彩与边缘：少一点重复配方

- 先确定整体偏暖还是偏冷，以及哪一处承担颜色重点。不要对所有参考机械地降饱和同一个比例。
- 深浅关系优先于颜色数量。若主体与背景粘在一起，先调明度或边缘，再考虑加新颜色。
- 阴影可以偏冷或偏暖，取决于光线与周围反射；不要把固定灰蓝当作所有画面的投影色。
- 色块溢出用于局部松动，不要每个物件都朝同一方向错位。结构关键位置仍要读得清。
- 水痕与颗粒在一张画里要有浓淡、大小和密度变化；留出安静区域，才能看见质地。
- 亮处可以留纸，也可以用浅色，取决于媒介；不要把所有洞口、眼白和高光都机械涂成纸色。
- 有些边缘用线，有些用色差，有些可以消失。先让关键形状可读，再减少不必要的边。

## 审图：做三种具体对照

### 1. 缩小看构图，再放大看线

把输出缩小到原尺寸约四分之一，观察先看到哪里、各物体是否可分辨、空白是否拥挤。
若缩小后主体不清楚，先改大小、间距、遮挡或明暗；不要先增加纹理。
再看原尺寸的关键轮廓：若长线像锯齿，减少高频抖动并修正控制点；若所有线像复制，调整不同线组的力度与中断位置。

### 2. 对照参考的三个识别特征

选出实际可观察的三个特征，例如“杯把明显高于杯身中点”“猫耳朝右”“左侧花瓣缺口”。逐项检查输出。
若杯把画错，改杯把控制点及接点；不要只调色或添细节。用户要求自由重构时，区分有意改变与意外丢失。
没有参考时改查轮廓、连接、支撑是否自洽；不要宣称“高度还原”。

### 3. 对照有无纹理、轻重两种局部版本

只对不确定区域保留两个版本：例如同一杯身减少一半排线，或保持轮廓不动去掉水痕。
若去掉纹理后形体才清楚，优先减少纹理；若两版都读不出体积，回到形状与明暗，而非继续加噪声。
记录具体差异和选择理由，不使用“AI 感 20 分”“自然度 90 分”等没有参照的评分。

## 反馈对应下一次改什么

| 用户反馈 | 先核对 | 下一次可改的具体内容 |
| --- | --- | --- |
| 太规整、像模板 | 是否等大等距、镜像轮廓、全部双描 | 调整主次大小与空白，保留参考中的不对称，只在局部补线 |
| 太乱、太脏 | 纹理是否铺满、排线是否穿过亮部 | 删次要线组，缩小暗部范围，留出连续的干净色面 |
| 不像原物 | 大比例、轮廓、接点、姿态是否改变 | 先修最影响识别的几何，不借“手绘风格”解释结构错误 |
| 太平、像图标 | 遮挡、明暗转折、线条轻重是否缺失 | 加一处有效的体积转折或接触阴影，减弱迎光边 |
| 太机械、太完美 | 是否缺少笔势、所有边都同样完整 | 在长线调整少量控制点，在次要亮边留缺口，控制重描范围 |
| 还想更自然 | 用户所指是构图、造型还是材质 | 根据画面先指出一个可见问题并改一处；判断仍不明确时问具体方向 |

## 局部重画保留已认可部分

- 为可独立调整的对象和线组使用稳定 id，例如 `cup-body-wash`、`cup-handle-ink`、`cat-back-hatch`；不要用数组顺序充当长期标识。
- 改位置、形状、颜色或笔触时，优先修改对应 id 的记录。其他已认可对象保持原数据与随机种子。
- 固定随机种子用于比较修改效果，不要每次反馈都更换整张图的随机结果；明确需要局部新的笔迹时，只给对应 mark 换一个 id 后缀，并保留旧版本。
- 局部重画后检查与邻近对象的接触、遮挡、光向及空间关系。稳定 id 帮助定位，不保证依赖区域自动更新。
- 保存修改前版本，并说明本次具体改变；“脚本成功”只证明输出完成，画得是否符合用户要求仍要看图。
